## 阶段 4 · 闭环收口：发货回写平台 ★★★

**目标**：**这是整个项目的核心，也是答辩的最高潮。**

### 步骤

| 步 | 做什么 | 说明 |
|---|---|---|
| 4.1 | 摸清 Shopify Fulfillment API 的两步流程 | 先查 `fulfillment_orders` 拿 ID |
| 4.2 | 先**用 Postman 手动调通**再写代码 | 关键：别直接写 Java |
| 4.3 | `SupplierAdapter.fetchTracking()` 抓回运单号 | 本地 `status` → `SHIPPED` |
| 4.4 | `PlatformAdapter.fulfill()` 实现回写 | 调 Shopify Fulfillment API |
| 4.5 | 回写成功 → `status` → `SYNCED` | 闭环完成 |
| 4.6 | 回写失败 → `sync_failed = true` | 预留补偿 |
| 4.7 | 新增接口 `POST /orders/{id}/sync-tracking` | 手动触发（后期可自动） |

### 验收标准 ★

**打开 Shopify 后台，那个订单真的从「未发货」变成了「已发货」，运单号在里面。**

**这一步通了，项目就成了一半。**

### ⚠️ 注意事项

- **先用 Postman 调通，再写 Java**。否则 Java 里的报错很难定位。
- Shopify 的发货是**两步**：
  1. `GET /orders/{id}/fulfillment_orders` → 拿 `fulfillment_order_id`
  2. `POST /fulfillments.json` → body 里带上那个 ID
- 记得带 `notify_customer: true`，买家会收到邮件（演示效果好）

**预计**：2 天

## 四、每个阶段结束时的自检

每完成一个阶段，问自己三个问题：

1. **能跑吗？** —— 代码编译通过、接口能调通
2. **能讲吗？** —— 能用一句话说清这个阶段做了什么、为什么这么做
3. **会崩吗？** —— 想一个最可能的失败场景，看自己答不答得上来

**第 2 条最重要**——答辩和面试考的都是"能不能讲清楚"。
